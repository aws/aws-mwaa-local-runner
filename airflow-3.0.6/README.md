# AWS MWAA Local Runner 3.0.6

This repository provides a local environment for testing Amazon Managed Workflows for Apache Airflow (MWAA) 3.0.6.

**Version:** 3.0.6  
**Airflow Version:** Apache Airflow 3.0.6  
**Python Version:** 3.12

## Quick Start

### Prerequisites

- **Docker Desktop** installed and running
- **Python 3.12** installed (for building Docker images)

### Step 1: Build the Docker Image

Build the MWAA Airflow 3.0.6 Docker image from the `amazon-mwaa-docker-images` repository:

```bash
git clone https://github.com/aws/amazon-mwaa-docker-images.git
cd amazon-mwaa-docker-images/images/airflow/3.0.6
python3 create_venvs.py
# Follow build instructions to create: amazon-mwaa-docker-images/airflow:3.0.6-dev
```

### Step 2: Start the Environment

```bash
cd docker
docker-compose -f docker-compose-local.yml up -d
```

### Step 3: Access Airflow UI

- **URL:** http://localhost:8081
- **Username:** `airflow`
- **Password:** `airflow`

> **Note:** Port 8081 is used to avoid conflicts with MWAA 2.10.3 (which uses 8080).

## Configuration

### Environment Variables

You have two options for setting environment variables (both are available):

#### Option 1: `.env` file (Recommended - Docker Compose standard)

Docker Compose automatically reads `.env` files. This is the recommended approach:

```bash
cd docker
cp .env.example .env
# Edit .env with your actual values
docker-compose -f docker-compose-local.yml up  # Automatically reads .env
```

**Format:** `KEY=VALUE` (standard Docker Compose format)

#### Option 2: `mwaa-local-env` file (Matches 2.10.3 style)

If you prefer the 2.10.3 workflow, use the shell script format:

```bash
cd docker
source mwaa-local-env  # Source the environment variables
docker-compose -f docker-compose-local.yml up
```

**Format:** `export KEY=value` (shell script format, must be sourced)

**Difference:**
- **`.env`**: Automatically read by Docker Compose (no need to source)
- **`mwaa-local-env`**: Shell script format, must be sourced before docker-compose (matches 2.10.3)

Both files are provided. Choose the one that fits your workflow. See `docker/README_ENV.md` for more details.

### Executor

Uses **LocalExecutor**:
- Tasks execute in the scheduler process
- No SQS or worker container needed
- **Note:** Airflow 3.0.6 requires Execution API even with LocalExecutor

### Services

- **PostgreSQL** (port 5433) - Metadata database
  - Container name: `mwaa-306-db`
- **Webserver** (port 8081) - Airflow UI and Execution API
  - Container name: `docker-webserver-1` (or similar, auto-generated)
  - Accessible at: http://localhost:8081
- **Scheduler** - DAG scheduler and task executor
  - Container name: `docker-scheduler-1` (or similar, auto-generated)
- **Migratedb** - Database initialization (runs once, then exits)
  - Container name: `docker-migratedb-1` (or similar, auto-generated)

> **Note:** Container names (except `mwaa-306-db`) are auto-generated by Docker Compose based on the project name. You can check actual names with: `docker-compose -f docker-compose-local.yml ps`

## Usage

### Adding DAGs

1. Add DAG files to `dags/` folder
2. Scheduler will discover them automatically (30-60 seconds)
3. **Important:** Use Airflow 3.0 syntax:
   - `schedule` instead of `schedule_interval`
   - `logical_date` instead of `execution_date`

### Adding Dependencies

1. Add packages to `requirements/requirements.txt`
2. Restart containers: `docker-compose -f docker-compose-local.yml restart`

### Stopping the Environment

```bash
cd docker
docker-compose -f docker-compose-local.yml down
```

To remove volumes (database data):
```bash
docker-compose -f docker-compose-local.yml down -v
```

## Differences from 2.10.3

See [DIFFERENCES.md](DIFFERENCES.md) for a detailed comparison.

**Key differences:**
- Uses `amazon-mwaa-docker-images/airflow:3.0.6-dev` image
- Separate `webserver` and `scheduler` services
- Execution API required (even for LocalExecutor)
- Airflow 3.0 syntax (`schedule`, `logical_date`)
- `.env` file instead of `mwaa-local-env`

## Testing

After starting the environment, verify everything works:

### 1. Check Container Status

```bash
cd docker
docker-compose -f docker-compose-local.yml ps
```

You should see:
- `postgres` - Running (healthy)
- `migratedb` - Exited (completed successfully)
- `webserver` - Running
- `scheduler` - Running

### 2. Access Airflow UI

- **URL:** http://localhost:8081
- **Username:** `airflow`
- **Password:** `airflow`

Verify the UI loads and you can log in.

### 3. Verify Sample DAGs

1. Wait 30-60 seconds for scheduler to discover DAGs
2. Check the DAG list in the UI
3. You should see 3 sample DAGs:
   - `sample_dag_mwaa_3_0`
   - `sample_taskflow_api_dag`
   - `sample_airflow_3_syntax_dag`

### 4. Test DAG Execution

1. Unpause one of the sample DAGs (toggle switch)
2. Trigger a manual run (play button)
3. Monitor task execution in the Graph/Tree view
4. Check task logs to verify successful execution

### 5. Test Environment Variables

If you created a `.env` file:
1. Add a test variable to `docker/.env`
2. Reference it in `docker-compose-local.yml`
3. Restart containers and verify it's loaded

## Troubleshooting

### Database Issues

```bash
cd docker
docker-compose -f docker-compose-local.yml down -v
docker-compose -f docker-compose-local.yml up -d
```

### DAGs Not Appearing

- Wait 30-60 seconds for scheduler discovery
- Check logs: `docker-compose -f docker-compose-local.yml logs scheduler`
- Verify DAG syntax is Airflow 3.0 compatible

### Port Conflicts

Change port in `docker-compose-local.yml`:
```yaml
ports:
  - "8082:8080"  # Use any available port
```

### Container Issues

Check container logs:
```bash
# Check all logs
docker-compose -f docker-compose-local.yml logs

# Check specific service
docker-compose -f docker-compose-local.yml logs webserver
docker-compose -f docker-compose-local.yml logs scheduler
```

### Configuration Review

If you encounter issues:
1. Verify Docker image is built: `docker images | grep "amazon-mwaa-docker-images/airflow:3.0.6-dev"`
2. Check environment variables are set correctly (if using `.env` file)
3. Verify ports 8081 and 5433 are not in use by other services
4. Review `docker-compose-local.yml` for any misconfigurations
